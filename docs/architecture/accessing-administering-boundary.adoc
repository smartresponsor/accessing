= Accessing Boundary for Administering Integration

Accessing owns identity, authentication, login/logout, session, password, 2FA, verification, user lock state, and security events.

Accessing must not become the full application ACL owner. Dynamic roles, permissions, ACL hierarchy, policy decisions, approval, delegation, and override logic belong to Rolling.

For Administering integration, Accessing exposes current-user context only. Administering and Rolling may map that user into a policy subject such as `accessing:user:{id}`.

The `roles` field on `AccessUserEntity` is reserved for Symfony bootstrap/security-shell roles such as `ROLE_USER` or `ROLE_ADMIN_BOOTSTRAP`. It is not the canonical application ACL hierarchy.
