= Accessing Controlled Admin Actions

Accessing owns identity, login, logout, sessions, passwords, 2FA state, verification, reset-password, and security events.

Administering may request user administration actions, but Accessing must execute them through Accessing-owned services.
This prevents Administering from raw-editing user internals.

== Allowed action examples

* lock user
* unlock user
* terminate session
* request 2FA reset
* view security events

== Forbidden admin raw edits

* password hash
* TOTP secret
* recovery codes
* raw session payloads
* verification internals

== Contract

`AccessingAdministrationServiceInterface` is the safe surface for Administering-triggered user actions.
