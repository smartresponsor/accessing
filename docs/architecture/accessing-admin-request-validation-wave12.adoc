= Wave 12: Controlled User Request Validation

Accessing now validates `AccessingAdministrationRequest` before the bridge delegates to the controlled user administration service.

Validation checks that:

* the requested action exists in the Accessing-controlled action catalog
* the user reference is non-empty
* the requesting subject is non-empty
* the safe reason is non-empty

The validator returns `AccessingAdministrationResult`, so validation failure uses the same safe result channel as execution failure.

The bridge records audit metadata for both rejected validation and execution results.

Accessing remains the owner of user, login, logout, session, password, 2FA, recovery, verification, and security event internals.
