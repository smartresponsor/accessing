= Accessing Controlled Admin Actions

Accessing remains the owner of user identity, login/logout, session, password, 2FA, verification, reset-password, and security events.

Administering may request controlled user actions through `AccessingAdministrationServiceInterface`, but it must not raw-edit Accessing internals.

== Allowed action classes

* lock user
* unlock user
* terminate session
* request 2FA reset
* view security events

== Forbidden direct edits

* password hash
* TOTP secret
* recovery codes
* raw session payload
* verification internals
* reset-password token internals

== Authorization

Accessing does not decide dynamic admin permissions.
Administering asks Rolling for authorization before invoking Accessing user actions.
